# Workflow: Existing Website Redesign

The prime directive: **improve the design without losing anything that works.**

1. **Inspect the current website and code.** Screenshot the live/staging pages at the standard widths (`scripts/shoot.mjs`, defaults 390x844 / 768 / 1280x800 / 1440x900; add `--full` and `--no-js`). Read the stack, theme, tokens/globals, templates. Elementor: run the inspection in `references/wordpress-elementor.md` §1.
2. **Understand its design language.** Extract the current system (`references/design-systems.md` §4). Note what is distinctive and good.
3. **Record existing content and functionality: the preservation ledger.** For each page in scope, list: headings and copy blocks, links (internal/external/tel/mailto), forms and their fields and actions/integrations, interactive widgets (sliders, tabs, booking, maps, chat), tracking/analytics IDs and classes, SEO elements (title, meta, H1, schema), and media. Save it (in chat or in a `redesign-ledger.md` in the project, if the user agrees to a file).
4. **Identify visual and UX weaknesses.** Run `workflows/design-critique.md` on the current state (score it, so improvement is measurable). Run `checklists/anti-ai-design-audit.md` if the site looks generated.
5. **Establish what must be preserved.** Brand marks, colors and fonts (unless a new identity is requested), content and claims, URLs/slugs, functions, integrations, things users rely on. Decide the depth with the user: **polish** (keep layout and system, fix details), **restyle** (keep structure, new visual system), or **full redesign** (new structure and system, same content and function). Don't blend depths.
6. **Research and propose a new creative direction** (for restyle/full). Run visual research at the Section or Full tier (`references/visual-research.md`), synthesize, and give before/after reasoning. For polish depth, research is optional (Light tier). **Stop for approval** before large changes unless the user said to proceed.
7. **Redesign the layout.** Section by section, mapping every ledger item to its new home. Nothing silently dropped. Content removals require agreement. **Exception:** content that appears fabricated (unverifiable testimonials, invented metrics, logo walls without permission) must not be carried forward as real. Replace it with a labeled placeholder, flag it as P0 in the handoff, and ask the client to supply real, attributable proof. Record it in the ledger as "removed: unverified".
8. **Implement using the existing technology.** Same CMS/framework. Work on a draft/staging copy or a new page, never directly on live pages without permission. Elementor: restyle through Globals and Theme Style first (site-wide wins), then page-level containers/widgets.
9. **Test responsive behavior** at all widths (`checklists/responsive-audit.md`), and check consistency across redesigned and untouched pages (`checklists/consistency-audit.md`). A redesigned page must not look foreign next to pages that weren't redesigned, or else plan their alignment.
10. **Verify existing functionality** against the ledger: every link resolves, every form submits with the same fields and actions, integrations fire, SEO elements present. Report counts ("14/14 links, 5/5 form fields, 2/2 tracking IDs preserved").
11. **Fresh-eyes review** (`agents/design-reviewer.md`, mandatory for redesigns), then **perform visual refinement** (`workflows/design-refinement.md`) and re-score. Ask: "What did the old page do better?" and keep it.
12. **Final audit:** `checklists/final-quality-gate.md`, with before/after scorecards and the ledger verification. Publish only with permission.
